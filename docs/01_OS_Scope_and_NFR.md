 Границы операционной системы и нефункциональные требования

 1. Название и концепция ОС

**StudyOS** — учебная операционная система с монолитным ядром, реализованная на Python с использованием SQLite в качестве дискового хранилища.

 2. Границы системы

 Входит в границы ОС:

| Компонент | Обоснование |
|-----------|-------------|
| Управление процессами | Создание, планирование, завершение процессов |
| Управление памятью | Выделение, освобождение, контроль лимита |
| Файловая система на SQLite | Хранение файлов в таблице files |
| Разграничение прав | Роли admin/user, проверка доступа |
| Командная оболочка | Интерфейс пользователя |
| Журналирование syscalls | Запись всех вызовов в syscalls_log |

 Не входит в границы ОС:

| Компонент | Обоснование |
|-----------|-------------|
| Реальная работа с железом | Требует знания драйверов, выходит за рамки учебной ОС |
| Поддержка прерываний | Сложно реализовать без аппаратного доступа |
| Сетевые протоколы | Не является темой проекта |
| Графический интерфейс | Не является темой проекта |

 3. Сценарии использования

 Сценарий 1: Вход в систему
- **Роль:** Пользователь
- **Системные вызовы:** sys_login
- **Модули:** shell.py → syscalls.py → kernel.py → auth.py → db.py

 Сценарий 2: Создание файла
- **Роль:** Пользователь
- **Системные вызовы:** sys_create_file
- **Модули:** shell.py → syscalls.py → fs.py → db.py

 Сценарий 3: Чтение файла
- **Роль:** Пользователь
- **Системные вызовы:** sys_read_file
- **Модули:** shell.py → syscalls.py → fs.py → db.py

 Сценарий 4: Запуск процесса
- **Роль:** Пользователь
- **Системные вызовы:** sys_exec
- **Модули:** shell.py → syscalls.py → kernel.py → scheduler.py → db.py

 Сценарий 5: Просмотр процессов
- **Роль:** Пользователь
- **Системные вызовы:** sys_ps
- **Модули:** shell.py → syscalls.py → scheduler.py → db.py

 Сценарий 6: Завершение процесса
- **Роль:** Администратор
- **Системные вызовы:** sys_kill
- **Модули:** shell.py → syscalls.py → auth.py → scheduler.py → db.py

 Сценарий 7: Просмотр журнала
- **Роль:** Администратор
- **Системные вызовы:** sys_logs
- **Модули:** shell.py → syscalls.py → db.py

 4. Нефункциональные требования

 Производительность
- **NFR-1:** Время обработки системного вызова ≤ 50 мс
- **NFR-2:** ОС выдерживает 10 одновременных процессов
- **NFR-3:** Время запуска оболочки ≤ 2 секунд

 Надёжность
- **NFR-4:** Ошибка в процессе не роняет ядро
- **NFR-5:** При попытке выделения памяти сверх лимита — отказ

 Безопасность
- **NFR-6:** Пароли хранятся в виде хэша SHA-256
- **NFR-7:** User не может удалить файл Admin
- **NFR-8:** Все системные вызовы логируются

 Поддерживаемость
- **NFR-9:** Код разбит на модули ≤ 300 строк
- **NFR-10:** Каждый модуль решает одну задачу

 Ресурсоёмкость
- **NFR-11:** ОС работает без внешних СУБД
- **NFR-12:** Только стандартная библиотека Python

 5. Анализ рисков

| Риск | Минимизация |
|------|-------------|
| Нехватка времени | Приоритизация: ядро → БД → ФС → оболочка |
| Блокировки SQLite | Единственное подключение, очередь запросов |
| Сложность отладки | Сквозное логирование |
| Забывчивость об ошибках | Чек-лист обработки исключений |
| Потеря концентрации | Ведение документации |

 6. Словарь терминов

1. **Ядро** — центральный модуль ОС, управляющий ресурсами.
2. **Системный вызов** — интерфейс между пользователем и ядром.
3. **Процесс** — программа в момент выполнения.
4. **Поток** — легковесная единица выполнения.
5. **Планировщик** — модуль распределения процессорного времени.
6. **Виртуальная память** — механизм изоляции адресных пространств.
7. **Дескриптор** — числовой идентификатор открытого файла.
8. **Хэширование** — необратимое преобразование данных.
9. **Kernel Space** — защищённая область памяти ядра.
10. **User Space** — область памяти пользовательских программ.
